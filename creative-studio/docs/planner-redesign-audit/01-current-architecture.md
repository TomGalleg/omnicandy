## 4. Process and IPC structure

```
src/main/        Electron main process (Node): all files, secrets, AI calls, external programs
  index.ts (169 lines)         creates windows, ProjectManager, SettingsStore, wires services
  ipc.ts (1,788 lines)         registers almost every IPC handler; builds the Claude/agent tool sets (very large)
  planner/                     the Planner: store, service, MCP, chat, IPC (see doc 02)
  agentHarness/                the "Independent AI agent" loop (OpenAI/Gemini/local) (see doc 03)
  claudePartner.ts (894)       Claude (Claude Agent SDK) chat + tools
  integrations/                third-party program adapters (Blender, Unreal, Fusion, Resolve, ...) (see doc 05)
  liveApps.ts, liveTask.ts     the ArtCraft apps driven as live documents
  projects.ts, projectStore.ts project registry and one project's folder (see doc 04)
src/preload/index.ts (306)     contextBridge: exposes window.studio; planner API is generated by Object.fromEntries over method names
src/shared/                    types, zod schemas, pure rules. No Node/Electron. Imported by main AND renderer via @shared alias
src/renderer/src/              React UI (see doc 06)
```

* **Channel list**: `src/shared/ipc.ts` (647 lines) defines `IPC` channel names and the `StudioApi` TypeScript contract. The Planner is
  deliberately different: **one channel `planner:call`** (`src/main/planner/ipc.ts:18`) that takes `(method, args[])`; the preload turns
  a list of method names into functions (`src/preload/index.ts:299`). Typed contract: `src/shared/plannerApi.ts` (`PlannerApi`).
* **Trust**: every handler checks `isTrustedSender(e)` (`src/main/planner/ipc.ts:156`).
* **A second process**: `out/planner-mcp.cjs` is the planner as a stand-alone MCP server (source `src/main/planner/mcpMain.ts`, built by
  `scripts/build-planner-mcp.mjs`). External AI tools (Claude Code, Gemini CLI) start it themselves; OmniCandy never launches it.
  It and the app write the same planner folder, made safe by a lock file (doc 04).
* **Third-party programs** are separate OS processes; OmniCandy embeds their windows into the Software tab (`embeddedApp.ts`,
  `windowTracker.ts`, `dockedPanel.ts`).

## 5. State management (the pattern, everywhere)

1. Truth lives in files owned by the main process (JSON per project / per plan; encrypted checkpoint for the agent).
2. The renderer asks main for a copy (`window.studio.*`), holds it in component state, and re-asks after every action.
3. There is **no push channel for planner data**. `PlannerWorkspace.tsx:65-74` polls `planner.list()` every 3 s and reloads the plan when its
   `revision` changed. Other areas use real push events: `window.studio.live.*` (live app state), `window.studio.agent.onChange`,
   `window.studio.claude.*`, `window.studio.external.onLive`.
4. Optimistic concurrency uses integer revisions (`rev` on items/tasks/assets, `metaRev` on the brief, `revision` / `planRevision` on a plan).

## 6. Where things are stored (summary; detail in doc 04)

| What | Location |
|---|---|
| App data root | `%APPDATA%\creative-studio` (Windows) or `~/.config/creative-studio` (Linux); override `CS_USER_DATA_DIR` (`src/main/index.ts:26`) |
| Project registry | `<userData>/projects.json` (`ProjectManager`, `src/main/projects.ts`) |
| Built-in project folder | `<userData>/projects/<key>/`; user-chosen default folder and per-project locations are recorded in the registry |
| One project | `<project>/project.json` (manifest) + `Assets/`, `Workflows/`, `Exports/`, `Versions/`, per-app folders, `Planner/` |
| A project's plan | `<project>/Planner/projects/<planId>/project.json`, `history.jsonl`, `chat.json`, `raw/` |
| Older (pre-project-plan) plans | `<userData>/planner/projects/<planId>/...` (the "shared folder") |
| Claude chat history | `ProjectStore.readClaudeHistory/writeClaudeHistory` inside the project |
| Agent checkpoint | `<project>/.omnicandy-agent-checkpoint.enc` (encrypted with Electron `safeStorage`) |
| API keys | credential vault under `<userData>/secrets` (`credentialVault.ts`, `platform/secureStorage.ts`); lent per call, never sent to the renderer |
| Spending | `ProjectStore.spending / recordSpend` (per project) |
